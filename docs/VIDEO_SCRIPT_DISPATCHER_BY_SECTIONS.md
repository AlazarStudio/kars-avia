# Видео-инструкция «Разделы диспетчера по порядку» — сценарий записи

Вариант без авторизации: начинаем с уже открытой системы и идём **по меню сверху вниз**, категория за категорией, пункт за пунктом. Порядок в сценарии = порядок в рельсе меню суперадмина.

Ориентир: **45 минут** основной части. Блоки, помеченные `[опц.]`, вырезаются первыми, если время поджимает.
Записывать под **SUPERADMIN** — видны все 18 пунктов. Отличия роли «Диспетчер» помечены `Δ`.

Второй сценарий (с входом в систему, по бизнес-логике «справочники → заявка → размещение → отчёт») — в [VIDEO_SCRIPT_DISPATCHER.md](VIDEO_SCRIPT_DISPATCHER.md). Приложения A и C оттуда (карта маршрутов и шпаргалка ловушек записи) годятся и для этого сценария.

---

## Перед записью, коротко

- Окно ≥ 1440 px, масштаб 100%, всё в одном окне: половина экранов открывается правыми сайдбарами.
- Сбросить залипшие состояния: фильтры статусов в Эскадрилье и ФАП поставить на «Все», вид — «Список», в карточке гостиницы открыть таб «Шахматка», в карточке АК — «Пользователи» (система запоминает последний открытый таб и откроет его же).
- Данные на стенде: заявка эскадрильи «Создан» и «Размещен», заявка ФАП «В работе» с наполненными услугами, заявка трансфера «Ожидание обработки» + водитель онлайн, гостиница с номерным фондом и тарифами, авиакомпания с ценником, черновик отчёта v2, договор с истекающим сроком, тикет поддержки.
- Не показывать: иконку `</>` в шапке (Script Runner), публичную ссылку на гостиницу целиком, уведомление про резерв (ведёт на несуществующую страницу).

## 0. Вступление — 1:00

- Kars Avia — система размещения экипажей и пассажиров авиакомпаний в гостиницах. Диспетчер создаёт заявки, подбирает гостиницы, ведёт статусы, закрывает период отчётом.

# КАТЕГОРИЯ «ЗАЯВКИ»

## 1. Эскадрилья — 12:00

`Заявки → Эскадрилья` (`/relay?page=1`). Заявки на размещение **экипажа**.

### 1.1 Список и фильтры (3:00)
- Строка управления слева направо: **иконка фильтра с бейджем → «Список» / «Группы» → «Поиск» → «Создать заявку»**.
- Колонки: **«№», «ФИО», «Дата заявки», «Авиакомпания», «Аэропорт», «Прибытие», «Отъезд», «Статус»**.
- Разобрать строку: номер, ФИО + должность второй строкой, логотип АК, код аэропорта, даты, пилюля статуса, бейдж непрочитанных сообщений. Вместо ФИО может стоять **«Предварительная бронь»** — заявка без конкретного человека.
- Полупрозрачные строки — «Готов к архиву» и «Отменен».
- Поповер **«Фильтры»**: **«Авиакомпания» → «Аэропорт» → «Период» → «Статус»**, справа «Сбросить».
  - «Все авиакомпании» / «Все аэропорты» — это сброс, а не значение.
  - «Период» фильтрует **по датам заезда и выезда**, а не по дате создания заявки.
  - «Статус» — единственный способ увидеть архив и отменённые.
- «Поиск» серверный, по номеру и ФИО, срабатывает через полсекунды.
- Сказать: список живой, новая заявка появляется без обновления страницы.
- `Δ` Вид **«Группы»** есть только у суперадмина.

### 1.2 Статусы — объяснить один раз (1:30)
Открыть фильтр «Статус» и назвать все:

| Статус | Когда появляется |
|---|---|
| Создан | только создана, гостиницы нет |
| В обработке | взята в работу |
| Размещен | привязана к номеру в шахматке |
| Продлен | выезд сдвинут вперёд |
| Сокращен | выезд сдвинут назад (или заезд позже планового) |
| Ранний заезд | заезд сдвинут раньше |
| Перенесен | бронь перенесена в шахматке |
| Готов к архиву | из шахматки, ждёт закрытия |
| Архив | закрыта |
| Отменен | отменена, править нечего |

**Главный тезис:** статус нигде не выбирается из списка. **Система вычисляет его из действия** — сдвинули даты, разместили, отменили. Покажем в 1.5.

### 1.3 Создание заявки (2:30)
**«Создать заявку»** → правый сайдбар. Подсказка «* — обязательные поля».

1. **«Тип заявки»** — «Квота» (по умолчанию) или «Резерв».
2. **«Авиакомпания»** — обязательное; после выбора появляются поля сотрудника.
3. **«Сотрудник авиакомпании»** — в строке ФИО, должность, пол. Кнопка **«+»** открывает сайдбар «Добавить сотрудника».
4. Чекбокс **«Предварительная бронь»** — заявка без человека, поле сотрудника гаснет.
5. **«Аэропорт»** — обязательное; в опции код, название, город. **Отдельного поля «Город» нет — он берётся из аэропорта.**
6. Даты и время заезда/выезда, питание, примечание.

Сказать: фактически обязательны четыре вещи — авиакомпания, аэропорт, дата заезда, дата выезда. Время можно не указывать, но при размещении система спросит его отдельно.

`[опц.]` **Массовый импорт** (`Δ` только суперадмин): сегмент **«Массовая»** → зона **«Файл XLSX»** → карточка файла («строк: N», «заявок: N», «с замечаниями: N») → «Авиакомпания», «Аэропорт», «Тип заявки» → предпросмотр **«ЧЭ / Заезд / Рейс / Выезд / 1/2м / Связка»** → кнопка **«Импортировать N заявок»** (N — сумма «Количество ЧЭ», не число строк). Заголовки файла проверяются в браузере, строки — на сервере; при серверной ошибке не создаётся ни одна заявка.

### 1.4 Размещение: подбор гостиницы (2:00)
Заявка «Создан» → **«три точки» → «Разместить»**.

- Если время не указывали — экран **«Время заезда и выезда не указано»** с дефолтами «Заезд 14:00» / «Выезд 12:00».
- Сайдбар **«Выбрать гостиницу»**: поле **«Город»** заполнено городом из аэропорта заявки, ниже список **«Гостиницы»**.
- Карточка: фото, название, бейдж «Kars Avia», звёзды, адрес. У карточки с **«✕ Номерной фонд не добавлен»** кнопка «Выбрать» неактивна.
- Сказать: подбор идёт по городу аэропорта. Дальше два исхода — у гостиницы с саморазмещением заявка привязывается сразу, у остальных уходим в шахматку (покажем в разделе «Гостиницы»).

### 1.5 Карточка заявки, правка, статусы (2:00)
Клик по строке → правый сайдбар, в заголовке номер заявки.

- Табы: **«Общая», «Питание», «Цены», «Чат», «История»**. Набор зависит от фазы: до размещения виден «Цены» (расчёт по тарифам), после — «Питание» (факт). Это не баг.
- В блоке «Цены» показать подпись **«N ₽ / сут. × M сут.»** и объяснить **частичные сутки**: заезд раньше 06:00 → +1 сутки, раньше 14:00 → +0,5; выезд позже 18:00 → +1, позже 12:00 → +0,5. Поэтому M ≠ числу календарных дней.
- **«три точки»**, порядок пунктов: **«Перейти в шахматку», «Редактировать», «Разместить», «Отменить заявку»** (красный).
- **Показать машину статусов вживую, три сохранения подряд:** сдвинуть «Выезд» вперёд → **«Продлен»**; сдвинуть «Выезд» назад → **«Сокращен»**; сдвинуть «Заезд» раньше → **«Ранний заезд»**. Сказать: заезд позже планового даёт «Сокращен», а не «Перенесен»; «Перенесен» и «Готов к архиву» ставит только шахматка.
- Показать **«Фактическое заселение»** с подсказкой «Если не указано — используется плановый заезд».
- Питание сохраняется своей кнопкой **«Сохранить питание»**.
- **«Отменить заявку»** → диалог «Вы действительно хотите отменить заявку?» → нажать **«Нет»**. После отмены меню «три точки» исчезает.
- Сказать: при пересечении дат с другой бронью сохранение не пройдёт, придёт конкретная ошибка.
- `Δ` Кнопка **«Отправить в архив»** есть только у роли «Диспетчер», в режиме правки, при статусе «Готов к архиву» — под этим аккаунтом её в кадре не будет.

### 1.6 Чат и история (1:00)
- Таб **«Чат»** с бейджем непрочитанных, переключатель **«Авиакомпания» / «Гостиница»** — два разных чата по одной заявке.
- Системные сообщения: **зелёные** — обычные, **красные** — про отмену. Сообщения суперадмина подписаны как **«Техническая поддержка»**.
- Смайлы вставляются в текст. **Вложений в чате нет** — не обещать «можно приложить документ».
- Кнопка **«↓»** отмечает прочитанным и прокручивает вниз.
- Таб **«История»** — кто и когда что поменял, с аватаром автора.
- Одной фразой: **в «Чате» люди договариваются, в «Истории» система пишет, что фактически изменилось в данных.**

## 3. ФАП v2 — 7:30

`Заявки → ФАП v2` (`/far`). Пассажиры задержанных рейсов.

Сказать сразу: здесь не «экипаж и номер в гостинице», а **пассажиры рейса и набор услуг** — проживание, трансфер, вода, питание, багаж.

### 3.1 Список (1:00)
- Заголовок «ФАП — заявки». Карточки: номер, статус-бейдж, авиакомпания, «Рейс …», аэропорт, дата.
- **Шесть точек услуг — не декор:** заливка = цвет услуги, зелёная галочка = «Завершён», оранжевая точка = «В работе», выключенная = «не подключено». Навести — всплывает подпись.
- Фильтры: «Авиакомпания», «Аэропорт», «Статус» («Все статусы», «Создан», «Принят», «В работе», «Завершён», «Отменён»), «Период». Поиск по рейсу и ФИО. Прокрутка догружает по 30.

### 3.2 Создание заявки (2:00)
**«Создать заявку»** → сайдбар.

1. «Введите авиакомпанию» → «Выберите аэропорт» → «Введите рейс» → «Дата рейса».
2. **«Состав заявки»**: «Пассажиры» (по умолчанию) и «Экипаж». **«Экипаж» неактивен, пока не выбрана авиакомпания** — состав берётся из её сотрудников.
3. **«Манифест»**: перетащить XLSX → разбор (число пассажиров, чипы «взр / РБ / инф», «Показать список»). Манифест сам подставляет номер рейса, а пассажиры попадают в реестр заявки.
4. **«Вид услуг»**: включить «Проживание» → количество человек, дата и время заезда/выезда; затем «Трансфер с аэропорта до гостиницы», «Поставка питьевой воды», «Поставка питания», «Доставка багажа» — у каждой свои количество и время.

### 3.3 Карточка заявки и статусы (1:30)
- Шапка: «Заявка {номер}», авиакомпания, «Рейс … · дата», **статус-пилл**, чип **«Реестр»** с числом, синяя кнопка **«Скачать отчёт»**, меню «⋯».
- Плитки услуг: статус, факт/план, процент, дедлайн; у «Проживания» — диапазон дат и сутки.
- Клик по статус-пиллу → **«Перевести в статус»** → «Принять заявку» → «Подтвердить». Повторить: «Начать выполнение».
- Сказать: переходы строго линейные — **Создан → Принят → В работе → Завершён**, перескочить нельзя. «Завершить заявку» и «Отменить заявку» необратимы, об этом написано в самих диалогах.

### 3.4 Реестр (1:00)
Чип **«Реестр»** → «Реестр — Пассажиры и экипаж».

- Счётчики «всего / пассажиров / экипаж / дети и инфанты», карточка **«Импорт манифеста»**, **«+ Добавить пассажира»** («ФИО *», «Телефон», «Место», «Категория», «Размещение»).
- Колонка услуг: чипы показывают, где человек уже задействован.
- Отметить однофамильцев → **«Связать в группу»** → «Тип связи» = «Семья».
- Два тезиса: реестр — **единый источник людей**, кнопка **«Из реестра»** во всех услугах берёт их отсюда; **«Категория» влияет на деньги** — ребёнок в отчёте по проживанию идёт со скидкой 50%, инфант бесплатно.

### 3.5 Услуги (1:00)
Показать две, остальные назвать.

- **«Поставка воды»**: KPI «Выдано / Осталось / Плановое время», быстрое добавление («ФИО *», «Телефон», «Место», «Категория»), кнопка **«Из реестра»** (уже добавленные помечены), «Выбрать все (N)» → «Удалить выбранных».
- **«Проживание»**: **«+ Добавить гостиницу»** → карточка с «размещено/мест» и кнопками «Сайт» / «Сканер» → «Открыть →». На странице гостиницы вкладка **«Пассажиры и экипаж»**: «Из реестра» → «Добавить выбранных», номера комнат, действия **«Переселить»** и **«Выселить»** (с причиной). Заселить сверх заявки можно — система спросит подтверждение и покажет бейдж «+N сверх заявки».

### 3.6 Отчёт по проживанию (1:00)
Страница гостиницы → вкладки **«Тарифы»** и **«Отчёт»**.

- «Тарифы»: **«+ Добавить тариф»** → название, **«Тип тарифа»** = «Койко-место» или «Номер», цены по видам размещения. Рядом «По договору авиакомпании» и «Тарифы гостиницы» — подставляются автоматически.
  Сказать: «Койко-место» — начисляем каждому гостю; «Номер» — один раз на номер.
- «Отчёт», режим «Редактирование»: группировка по номерам, «Тариф», «Сут.», «Питание», «Прожив.», кнопка **«Кол-во всем»**. «Ст-ть питания» руками не вводится — это сумма завтрака, обеда и ужина.
- **«Отправить на проверку»** заблокировано, пока отчёт не сохранён хоть раз. Отчёт сохраняется полной заменой строк — если правят двое, победит последний сохранивший.
- **«Скачать отчёт»** в шапке заявки — сводный XLSX.

## 4. Трансфер — 4:00

`Заявки → Трансфер` (`/orders`)

### 4.1 Список (1:30)
- Колонки: **«№ / Пассажиры / Авиакомпания / Дата и время / Подача / Пункт назначения / Статус»**.
- В колонке «№» — **таймер**: обратный отсчёт до подачи, «Просрочен», «Выполнен».
- **Сортировка по срочности, а не по дате создания:** сверху заявки, до подачи которых меньше 2 часов, затем сегодняшние, затем остальные.
- Строки «Завершена» и «Отменена» полупрозрачны.
- Фильтры: «Авиакомпания», «Организация», «Водитель», «Статус» (мультивыбор), «Период».
- Статусы дословно: **«Ожидание обработки», «Назначен водитель», «Принят водителем», «Водитель приехал», «В пути к клиенту», «В пути к месту назначения», «Завершена», «Отменена»**.

### 4.2 Создание (0:45)
**«Создать заявку»** → «Авиакомпания» → «Сотрудник авиакомпании» (мультивыбор) → «Адрес отправления» → «Адрес прибытия» → «Дата и время заказа» → комментарий, багаж.
Сказать: число пассажиров не вводится — это количество выбранных сотрудников. Без пассажиров заявка тоже создаётся, в списке будет «Предварительная бронь».

### 4.3 Карточка заявки и назначение водителя (1:45)
Клик по заявке «Ожидание обработки» → `/orders/<id>`.

- Слева карта: **красная метка** — подача, **фиолетовая** — пункт назначения, **синие** — водители онлайн.
- Блок **«Ближайшие машины (N)»**: только водители онлайн, самые свободные сверху; поиск по имени, госномеру, авто, организации.
- **«Назначить»** → модалка «Назначить водителя?» → «Назначить» → статус стал «Назначен водитель», метка водителя позеленела.
- Правая панель, таб «Общая»: маршрут, «Сотрудники», «Дата заказа», «Время заказа», «Комментарий», «Информация о багаже». Меню «три точки» → «Редактировать». Таб «Чат» — переписка по заявке.

## 14. Отчёты v2 — 4:30

`Инструменты → Отчёты v2`

### 14.1 Создание (1:30)
- Переключатель **«Авиакомпании» / «Гостиницы»**, поиск по отчётам, кнопки **«Правила расчёта»** и **«Создать отчёт»**.
- Сайдбар: «Тип отчёта» → «Авиакомпания» → **«Аэропорт»** (обязательный) → «Категория» / «Должность» / «Сотрудник» → блок **«Включить в отчёт»** (Проживание / Питание, хотя бы одно) → период.
- Галка **«Проверить строки перед выгрузкой»** — ключевая развилка: **без галки** один шаг и сразу Excel (так выпускается большинство отчётов), **с галкой** создаётся черновик для проверки.
- Про период: на сервер уходят не «даты», а `дата T00:10` и `дата T23:50`. Это часть расчёта, а не форматирование: сервер по этим границам обрезает заявку, и обрезанный край попадает в правила частичных суток.

### 14.2 Черновик (2:00)
- Плашка **«Незавершённые черновики · N»** → «Открыть». Бейдж **«устарел»** = данные заявок могли измениться после создания черновика.
- Заголовок «Черновик · Компания · период», чип **«Предупреждения · N»** — строки без суток или без цены.
- Правка «Сут.», «Цена/сут.», питания; иконка **«Вернуть расчёт сервера»** для одной строки; ссылка **«Сбросить все правки»**; корзина → «Удалить строку из отчёта?» → чип «Удалено · 1».
- **Главный тезис:** пересчёт «сутки × цена» применяется **только к строкам, которые вы правили руками**. У нетронутых сумма приходит с сервера, где стоимость номера делится между соседями по временным сегментам — наивный пересчёт переписал бы чужие деньги.
- **«Подтвердить и выгрузить»**: при несохранённых правках система сначала сохранит, потом напечатает — печатается то, что лежит в базе, а не то, что на экране.
- Про размер: очень большой черновик может не сохраниться из-за лимита запроса, в интерфейсе это выглядит как «ничего не произошло» — разбивайте период.

### 14.3 Правила расчёта суток (1:00)
- **«Правила расчёта»** → сайдбар «Правила расчёта суток».
- **«Заезд»**: «раньше 06:00 → + 1 сут.», «раньше 14:00 → + 0.5 сут.». **«Выезд»**: «позже 12:00 → + 0.5 сут.», «позже 18:00 → + 1 сут.».
- Сказать: настройка одна общая на всю систему и применяется к **новым** отчётам; уже созданные черновики не пересчитываются — нужно пересоздать.
- `Δ` править может только суперадмин; у роли «Диспетчер» режим просмотра с плашкой «Изменять правила может только супер-администратор».
