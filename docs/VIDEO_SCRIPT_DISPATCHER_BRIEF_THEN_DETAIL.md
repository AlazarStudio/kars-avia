# Видео-инструкция «Разделы диспетчера: коротко → подробно» — сценарий записи

Третий вариант сценария. Формат каждого раздела одинаковый:

> **Коротко** — 1–2 предложения на обзорном экране: что это за раздел и зачем он диспетчеру. Говорим, пока экран просто открыт, ничего не нажимая.
> **Подробно** — сразу после, по шагам: что нажать, что заполнить, что сказать.

Порядок разделов — как в меню, сверху вниз. Без входа в систему: начинаем с уже открытой системы.
Ориентир: **48 минут**. Блоки `[опц.]` режутся первыми. Записывать под **SUPERADMIN**, отличия роли «Диспетчер» помечены `Δ`.

Родственные файлы: [VIDEO_SCRIPT_DISPATCHER.md](VIDEO_SCRIPT_DISPATCHER.md) — вариант с входом и по бизнес-логике (там же приложение A «карта маршрутов» и приложение C «ловушки записи», годятся и здесь); [VIDEO_SCRIPT_DISPATCHER_BY_SECTIONS.md](VIDEO_SCRIPT_DISPATCHER_BY_SECTIONS.md) — тот же порядок разделов без разделения «коротко / подробно».

**Перед записью:** окно ≥ 1440 px, масштаб 100%; фильтры статусов в Эскадрилье и ФАП — на «Все», вид — «Список»; в карточке гостиницы заранее открыть таб «Шахматка», в карточке АК — «Пользователи» (система запоминает последний таб). Не показывать: иконку `</>` в шапке, публичную ссылку на гостиницу целиком, уведомление про резерв.

## 0. Вступление и меню — 1:30

**Коротко.** Kars Avia — система размещения экипажей и пассажиров авиакомпаний в гостиницах: диспетчер создаёт заявки, подбирает гостиницы, ведёт статусы и закрывает период отчётом. Навигация двухуровневая: слева рельс из четырёх категорий, справа от него панель с пунктами выбранной категории.

**Подробно.**
1. Пройти по четырём категориям рельса: **«Заявки»** — ежедневная работа, **«Управление»** — контрагенты и люди, **«Инструменты»** — договоры, отчёты, аналитика, **«Сервис»** — поддержка и база знаний.
2. Показать синие бейджи на пунктах и расшифровать: Эскадрилья считает заявки в статусе «Создан», ФАП v2 — в статусе «Создан», Трансфер — в «Ожидание обработки». Счётчики живые, обновляются без F5.
3. Ввести пару букв в **«Поиск в разделе»** — фильтруются пункты текущей категории; при переключении категории поиск сбрасывается.
4. Нажать шеврон внизу рельса — панель свернулась до полосы иконок; состояние запоминается между сессиями.
5. Сказать: пойдём по меню сверху вниз. Три потока заявок не смешиваются — **Эскадрилья** это экипаж, **ФАП** это пассажиры задержанного рейса, **Трансфер** это машины.

## 1. Шапка страницы — 0:40

**Коротко.** Верхняя строка одинакова на всех экранах: слева название текущего раздела, справа — чат техподдержки, колокольчик уведомлений, дата и аватар. Через аватар открывается профиль и выход.

**Подробно.**
1. Показать, что заголовок слева меняется от раздела к разделу — это всегда название того, что открыто.
2. Иконка наушников — **чат с техподдержкой**, красный кружок на ней это число непрочитанных сообщений.
3. Колокольчик → панель **«Уведомления»** с табами **«Все» / «Эскадрилья» / «ФАП» / «Трансфер»** — это серверный фильтр по типу события. Записи сгруппированы по дням, прокрутка догружает по 50, в конце «Это все уведомления».
4. Иконка справа в строке уведомления — переход к объекту: по заявке эскадрильи откроется её сайдбар, по ФАП — страница заявки. **У иконки нет подписи, проговорить голосом.**
5. Сказать: красная точка на колокольчике зажигается на событие текущей сессии и не гаснет после прочтения — это индикатор «что-то произошло», а не счётчик непрочитанных.
6. Клик по аватару → сайдбар профиля: **«Мой профиль»**, **«Вход и безопасность»**, **«Помощь»**, **«Техподдержка»**, иконка выхода. Кебаб (три точки) — единственный вход в режим правки, до него поля неактивны специально.
7. Не обещать: телефон в профиле не правится, выбора темы интерфейса нет.

# КАТЕГОРИЯ «ЗАЯВКИ»

## 2. Эскадрилья — 12:00

**Коротко.** Главный рабочий список: заявки на размещение членов экипажа — кто, какая авиакомпания, какой аэропорт, даты заезда и выезда, статус. Отсюда заявка создаётся, отсюда же уходит в гостиницу и здесь же ведётся до архива.

**Подробно — список и фильтры (3:00).**
1. Строка управления слева направо: **иконка фильтра с бейджем → переключатель «Список» / «Группы» → «Поиск» → «Создать заявку»**.
2. Назвать колонки: **«№», «ФИО», «Дата заявки», «Авиакомпания», «Аэропорт», «Прибытие», «Отъезд», «Статус»**.
3. Разобрать одну строку: номер заявки, ФИО с должностью второй строкой, логотип авиакомпании, код аэропорта, даты, цветная пилюля статуса, бейдж непрочитанных сообщений.
4. Показать строку с **«Предварительная бронь»** вместо ФИО — это заявка без конкретного человека, и полупрозрачные строки — статусы «Готов к архиву» и «Отменен».
5. Открыть поповер **«Фильтры»**: поля **«Авиакомпания» → «Аэропорт» → «Период» → «Статус»**, справа «Сбросить», на кнопке бейдж с числом активных фильтров.
6. Сказать три вещи про фильтр: «Все авиакомпании» / «Все аэропорты» — это сброс, а не значение; «Период» фильтрует **по датам заезда и выезда**, а не по дате создания заявки; «Статус» — единственный способ увидеть архив и отменённые.
7. Набрать номер или фамилию в **«Поиск»** — серверный поиск срабатывает через полсекунды.
8. Сказать: список живой, новая заявка появляется без обновления страницы. `Δ` вид **«Группы»** есть только у суперадмина.

**Подробно — статусы (1:30).** Открыть фильтр «Статус» и назвать все:

| Статус | Когда появляется |
|---|---|
| Создан | только создана, гостиницы нет |
| В обработке | взята в работу |
| Размещен | привязана к номеру в шахматке |
| Продлен | выезд сдвинут вперёд |
| Сокращен | выезд сдвинут назад (или заезд позже планового) |
| Ранний заезд | заезд сдвинут раньше |
| Перенесен | бронь перенесена в шахматке |
| Готов к архиву | из шахматки, ждёт закрытия |
| Архив | закрыта |
| Отменен | отменена, править нечего |

Главный тезис: **статус нигде не выбирается из списка — система вычисляет его из действия.** Покажем вживую ниже.

**Подробно — создание заявки (2:30).**
1. **«Создать заявку»** → правый сайдбар, сверху подсказка «* — обязательные поля».
2. **«Тип заявки»** — «Квота» по умолчанию, либо «Резерв».
3. **«Авиакомпания»** — обязательное; только после выбора появляются поля сотрудника.
4. **«Сотрудник авиакомпании»** — в строке видно ФИО, должность и пол; кнопка **«+»** открывает сайдбар «Добавить сотрудника».
5. Чекбокс **«Предварительная бронь»** — заявка без конкретного человека, поле сотрудника гаснет.
6. **«Аэропорт»** — обязательное; в опции код, название и город. Отдельного поля «Город» нет, он берётся из аэропорта.
7. Даты и время заезда/выезда, питание, примечание.
8. Сказать: фактически обязательны четыре вещи — авиакомпания, аэропорт, дата заезда, дата выезда. Время можно не указывать, но при размещении система спросит его отдельно.

**Подробно — массовый импорт (2:00) `[опц.]`, `Δ` только суперадмин.**
1. В том же сайдбаре переключиться на сегмент **«Массовая»**.
2. Перетащить файл в зону **«Файл XLSX»** («Перетащите файл или выберите на компьютере»).
3. Показать карточку файла: имя, «строк: N», «заявок: N», при проблемах «с замечаниями: N», кнопки «Заменить» и «Убрать файл».
4. Заполнить «Авиакомпания», «Аэропорт», проверить «Тип заявки».
5. Показать предпросмотр — таблица **«ЧЭ / Заезд / Рейс / Выезд / 1/2м / Связка»**, подсвеченные строки это замечания (импорт они не блокируют).
6. Нажать **«Импортировать N заявок»**. Сказать: N — это сумма «Количество ЧЭ», а не число строк файла; заголовки проверяются в браузере, содержимое строк на сервере, и при серверной ошибке не создаётся ни одна заявка.

**Подробно — размещение (2:00).**
1. Открыть заявку в статусе «Создан» → **«три точки» → «Разместить»**.
2. Если время не указывали — сначала экран **«Время заезда и выезда не указано»** с дефолтами «Заезд 14:00» / «Выезд 12:00».
3. В сайдбаре **«Выбрать гостиницу»** показать: поле **«Город»** уже заполнено городом из аэропорта заявки, ниже список **«Гостиницы»**.
4. Пройтись по карточке: фото, название, бейдж «Kars Avia», звёзды, адрес. Показать карточку с **«✕ Номерной фонд не добавлен»** — у неё кнопка «Выбрать» неактивна.
5. Сменить город — список перезагружается; в городе без гостиниц видно «В этом городе нет доступных гостиниц».
6. Сказать: дальше два исхода — у гостиницы с саморазмещением заявка привязывается сразу, у остальных диспетчер уходит в шахматку и раскладывает вручную (покажем в разделе «Гостиницы»).

**Подробно — карточка заявки и статусы вживую (2:00).**
1. Клик по строке → правый сайдбар, в заголовке номер заявки. Табы: **«Общая», «Питание», «Цены», «Чат», «История»**.
2. Сказать: набор табов зависит от фазы заявки — до размещения виден «Цены» (расчёт по тарифам), после размещения «Питание» (факт). Это не баг.
3. В блоке «Цены» показать подпись **«N ₽ / сут. × M сут.»** и объяснить частичные сутки: заезд раньше 06:00 → +1 сутки, раньше 14:00 → +0,5; выезд позже 18:00 → +1, позже 12:00 → +0,5. Поэтому M не равно числу календарных дней.
4. Открыть **«три точки»**: **«Перейти в шахматку», «Редактировать», «Разместить», «Отменить заявку»** (последний красный).
5. Сделать три сохранения подряд: сдвинуть **«Выезд» вперёд** → статус **«Продлен»**; сдвинуть **«Выезд» назад** → **«Сокращен»**; сдвинуть **«Заезд» раньше** → **«Ранний заезд»**.
6. Сказать: заезд позже планового даёт «Сокращен», а не «Перенесен»; «Перенесен» и «Готов к архиву» ставит только шахматка.
7. Показать **«Фактическое заселение»** с подсказкой «Если не указано — используется плановый заезд». Питание сохраняется своей кнопкой **«Сохранить питание»**.
8. **«Отменить заявку»** → диалог «Вы действительно хотите отменить заявку?» → нажать **«Нет»**. Сказать: после отмены меню «три точки» исчезает, править нечего. При пересечении дат с другой бронью сохранение не пройдёт и придёт конкретная ошибка.
9. `Δ` Кнопка **«Отправить в архив»** есть только у роли «Диспетчер», в режиме правки и при статусе «Готов к архиву» — под этим аккаунтом её в кадре не будет, сказать словами.

**Подробно — чат и история (1:00).**
1. Таб **«Чат»** с бейджем непрочитанных; переключатель **«Авиакомпания» / «Гостиница»** — это два разных чата по одной заявке.
2. Показать системные сообщения: **зелёные** обычные, **красные** про отмену. Сообщения суперадмина подписываются как **«Техническая поддержка»**.
3. Нажать смайл — символ вставляется в текст. **Вложений в чате нет**, не обещать «можно приложить документ».
4. Кнопка **«↓»** отмечает всё прочитанным и прокручивает вниз.
5. Таб **«История»** — кто и когда что поменял, с аватаром автора.
6. Итог одной фразой: **в «Чате» люди договариваются, в «Истории» система пишет, что фактически изменилось в данных.**

## 3. ФАП v1 — 0:30

**Коротко.** Предыдущая версия интерфейса для пассажирских заявок, оставлена рядом с v2. Это не отдельный реестр: v1 и v2 — два интерфейса над одними и теми же данными, заявка из одного видна в другом.

**Подробно.** Открыть, показать таблицу и соседство пунктов «ФАП v1» и «ФАП v2» в меню — это снимает главный вопрос зрителя. Внутрь не заходить. Сказать: штатно работаем в v2, к нему и переходим.

## 4. ФАП v2 — 7:30

**Коротко.** Заявки на обслуживание пассажиров задержанного рейса. Здесь не «экипаж и номер в гостинице», а **рейс и набор услуг**: проживание, трансфер, вода, питание, багаж — каждая со своим статусом и своим списком людей.

**Подробно — список (1:00).**
1. Заголовок «ФАП — заявки». Разобрать карточку: номер заявки, статус-бейдж, авиакомпания, «Рейс …», аэропорт, дата создания.
2. Навести на шесть точек услуг — **это не декор**: заливка = цвет услуги, зелёная галочка = «Завершён», оранжевая точка = «В работе», выключенная = «не подключено».
3. Фильтры: «Авиакомпания», «Аэропорт», «Статус» («Все статусы», «Создан», «Принят», «В работе», «Завершён», «Отменён»), «Период». Поиск по рейсу и ФИО. Прокрутка догружает по 30, в конце «Больше заявок нет».

**Подробно — создание (2:00).**
1. **«Создать заявку»** → сайдбар. Заполнить «Введите авиакомпанию» → «Выберите аэропорт» → «Введите рейс» → «Дата рейса».
2. Блок **«Состав заявки»**: «Пассажиры» включены по умолчанию, рядом «Экипаж». Сказать: **«Экипаж» неактивен, пока не выбрана авиакомпания** — состав берётся из её сотрудников.
3. Блок **«Манифест»**: перетащить XLSX → показать разбор (число пассажиров, чипы «взр / РБ / инф», «Показать список»). Сказать: манифест сам подставляет номер рейса, а люди попадают в реестр заявки.
4. Блок **«Вид услуг»**: включить «Проживание» → количество человек, дата и время заезда и выезда. Затем «Трансфер с аэропорта до гостиницы», «Поставка питьевой воды», «Поставка питания», «Доставка багажа» — у каждой свои количество и время.
5. Создать. Если система нашла похожую заявку — покажет предупреждение о дубликате.

**Подробно — карточка и статусы (1:30).**
1. Шапка: «Заявка {номер}», авиакомпания, «Рейс … · дата», **статус-пилл**, чип **«Реестр»** с числом, синяя кнопка **«Скачать отчёт»**, меню «⋯».
2. Пройти по плиткам услуг: статус, факт/план, процент, дедлайн; у «Проживания» — диапазон дат и сутки.
3. Клик по статус-пиллу → поповер **«Перевести в статус»** → «Принять заявку» → «Подтвердить». Повторить: «Начать выполнение».
4. Сказать: переходы строго линейные — **Создан → Принят → В работе → Завершён**, перескочить нельзя. «Завершить заявку» и «Отменить заявку» необратимы, об этом написано в самих диалогах.
5. Показать меню «⋯»: «Редактировать», «История», «Отменить заявку». На завершённой заявке правка и отмена скрыты.

**Подробно — реестр (1:00).**
1. Чип **«Реестр»** → «Реестр — Пассажиры и экипаж». Счётчики «всего / пассажиров / экипаж / дети и инфанты».
2. Карточка **«Импорт манифеста»** → «Добавить N в реестр».
3. **«+ Добавить пассажира»**: «ФИО *», «Телефон», «Место», «Категория», «Размещение».
4. Показать колонку услуг — чипы означают, что человек уже задействован в воде, питании, проживании, трансфере.
5. Отметить однофамильцев → **«Связать в группу»** → «Тип связи» = «Семья» → подпись.
6. Два тезиса: реестр — **единый источник людей**, кнопка **«Из реестра»** во всех услугах берёт их отсюда; **«Категория» влияет на деньги** — ребёнок в отчёте по проживанию идёт со скидкой 50%, инфант бесплатно.

**Подробно — услуги (1:00).** Показать две, остальные назвать.
1. Плитка **«Поставка воды»**: KPI «Выдано / Осталось / Плановое время», форма быстрого добавления («ФИО *», «Телефон», «Место», «Категория»), кнопка **«Из реестра»** (уже добавленные помечены), «Выбрать все (N)» → «Удалить выбранных».
2. Плитка **«Проживание»**: **«+ Добавить гостиницу»** → карточка с «размещено/мест» и кнопками «Сайт» / «Сканер» → «Открыть →».
3. На странице гостиницы вкладка **«Пассажиры и экипаж»**: «Из реестра» → «Добавить выбранных», проставить номера комнат, действия **«Переселить»** и **«Выселить»** (с причиной).
4. Сказать: заселить сверх заявки можно — система спросит подтверждение и потом покажет бейдж «+N сверх заявки».

**Подробно — отчёт по проживанию (1:00).**
1. На странице гостиницы вкладка **«Тарифы»** → **«+ Добавить тариф»** → название, **«Тип тарифа»** = «Койко-место» или «Номер», цены по видам размещения. Рядом секции «По договору авиакомпании» и «Тарифы гостиницы» — подставляются автоматически.
2. Сказать: «Койко-место» — начисляем каждому гостю, «Номер» — один раз на номер.
3. Вкладка **«Отчёт»**, режим «Редактирование»: группировка по номерам, по строке «Тариф», «Сут.», «Питание», «Прожив.», кнопка **«Кол-во всем»**. «Ст-ть питания» руками не вводится — это сумма завтрака, обеда и ужина.
4. Сказать: **«Отправить на проверку»** заблокировано, пока отчёт не сохранён хоть раз; отчёт сохраняется полной заменой строк — если правят двое, победит последний сохранивший.
5. Кнопка **«Скачать отчёт»** в шапке заявки — сводный XLSX.

## 5. Трансфер — 4:00

**Коротко.** Очередь заявок на машину: кому, куда и во сколько нужен транспорт. Диспетчер видит свободных водителей на карте, назначает машину, а дальше статусы ведёт сам водитель из мобильного приложения.

**Подробно — список (1:30).**
1. Назвать колонки: **«№ / Пассажиры / Авиакомпания / Дата и время / Подача / Пункт назначения / Статус»**.
2. Показать в колонке «№» **таймер**: обратный отсчёт до подачи, «Просрочен», «Выполнен».
3. Сказать про сортировку: **список отсортирован по срочности, а не по дате создания** — сверху заявки, до подачи которых меньше двух часов, затем сегодняшние, затем остальные.
4. Строки «Завершена» и «Отменена» полупрозрачны — это нормальное состояние.
5. Фильтры: «Авиакомпания», «Организация», «Водитель», «Статус» (мультивыбор), «Период».
6. Назвать все статусы: **«Ожидание обработки», «Назначен водитель», «Принят водителем», «Водитель приехал», «В пути к клиенту», «В пути к месту назначения», «Завершена», «Отменена»**.

**Подробно — создание (0:45).**
1. **«Создать заявку»** → «Авиакомпания» → «Сотрудник авиакомпании» (мультивыбор) → «Адрес отправления» → «Адрес прибытия» → «Дата и время заказа» → комментарий, багаж.
2. Сказать: число пассажиров не вводится, это количество выбранных сотрудников. Без пассажиров заявка тоже создаётся — в списке будет «Предварительная бронь».

**Подробно — назначение водителя (1:45).**
1. Клик по заявке «Ожидание обработки» → открылась страница заявки, в шапке статус и дата подачи.
2. Разобрать карту: **красная метка** — адрес подачи, **фиолетовая** — пункт назначения, **синие** — водители онлайн.
3. Блок **«Ближайшие машины (N)»**: в нём только водители онлайн, самые свободные сверху; поиск по имени, госномеру, авто, организации.
4. **«Назначить»** → модалка «Назначить водителя?» → «Назначить» → статус стал «Назначен водитель», метка водителя позеленела.
5. Правая панель, таб «Общая»: маршрут, «Сотрудники», «Дата заказа», «Время заказа», «Комментарий», «Информация о багаже». Меню «три точки» → «Редактировать». Таб «Чат» — переписка по этой заявке.
6. Сказать два факта: дальнейшие статусы («Принят водителем», «Водитель приехал», «В пути…») ставит водитель из приложения; блок «Ближайшие машины» есть только в первых трёх статусах и дальше исчезает — это не пропажа функции.

## 6. Авиакомпании — 5:00

**Коротко.** Реестр авиакомпаний-контрагентов и всё, что к ним относится: реквизиты, отделы и аккаунты, экипаж, договоры и — главное — цены, по которым считаются заявки. Пока у авиакомпании нет ценника, деньги по её заявкам не посчитаются.

**Подробно — список (1:00).**
1. Колонки **«ID» / «Название» / «Наименование» / «Статус»**; поиск серверный.
2. Клик по бейджу **«N/11»** в колонке «Статус» → попап **«Готовность к работе»**: чек-лист из 11 пунктов, чего в карточке не хватает. Это главный инструмент списка.
3. **«Добавить авиакомпанию»** → «Название» + логотип → «Добавить». Сказать: в форме создания только базовое, всё остальное — в карточке.

**Подробно — табы карточки (0:30).** Порядок слева направо: **«Пользователи» → «Цены» → «Цены на трансфер» → «Реестр договоров» → «Сотрудники» → «Об авиакомпании»**. Сказать: система запоминает последний открытый таб и откроет его же в следующей карточке.

**Подробно — «Об авиакомпании» (0:45).** Паспорт контрагента: под-табы «Общая информация» / «Реквизиты» / «Контакты и адрес», кнопки «История» и «Редактировать». Заполнить пару полей → «Сохранить» → вернуться к бейджу «N/11» и показать, что пункт закрылся.

**Подробно — «Цены» (1:45).**
1. Список ценников: название + бейдж **«Индивидуальный» / «Общий»** + бейдж **«Эскадрилья» / «ФАП» / «Все типы»**.
2. Раскрыть шевроном: блоки «Категории — цены», «Питание — цены», «Аэропорты» (или «География»).
3. **«Добавить договор»** → показать **два разных переключателя** и специально их разделить:
   **«Применяется к»** — для каких заявок эти цены (Эскадрилья / ФАП / Все типы);
   **«Тип договора»** — как привязаны локации («Индивидуальный» → мультиселект аэропортов, «Общий» → регионы и города).
4. Сказать: одна локация не может быть занята двумя конфликтующими ценниками — занятые аэропорты в мультиселекте заблокированы.
5. Коротко открыть таб **«Цены на трансфер»** — ставки по вместимости машины.

**Подробно — «Пользователи» и «Сотрудники» (1:00).**
1. «Пользователи»: отделы авиакомпании и аккаунты внутри них. **«Добавить»** → «Новый отдел» / «Новый пользователь». Бейдж **«N/3»** у отдела — чек-лист (почта / доступы / уведомления). Должность создаётся тут же по **«+»**.
2. Шестерёнка в строке отдела открывает доступы — механика та же, разберём подробно в разделе «Пользователи».
3. «Сотрудники» — экипаж с календарём размещений по месяцам. `Δ` под суперадмином сотрудника добавить нельзя: экипаж заводит сама авиакомпания.

## 7. Гостиницы — 6:30

**Коротко.** Реестр гостиниц-контрагентов: номерной фонд, тарифы, договоры и шахматка — экран, где заявка превращается в конкретную бронь в конкретном номере. Это самый плотный раздел системы, здесь диспетчер проводит больше всего времени.

**Подробно — список (1:00).**
1. Колонка **«Номерной фонд»** (Квота / Резерв / Мощность) и колонка **«Статус»** с пилюлей «N/M» → попап **«Готовность к работе»**.
2. Фильтры: «Город», «Аэропорт», «Оценка» (звёзды с полушагом), «Звёздность», **«Видимость»** (Скрытые → бейдж «Скрыта»), **«Статус»** (Неактивные → бейдж «Неактивна»).
3. **«Добавить гостиницу»**: «Название», «Город», «Аэропорт», «Адрес», «Мощность», «Оценка», «Звёздность», «Картинка» — всё обязательное; файл больше 8 МБ не примет.

**Подробно — табы карточки (0:30).** Порядок: **«Шахматка» → «Тарифы» → «Реестр договоров» → «Номерной фонд» → «Пользователи» → «О гостинице» → «Настройки»**. `Δ` у роли «Диспетчер» последний таб называется «Редактирование». Отдельно показать иконку **«Поделиться ссылкой»** справа в полосе табов: временная ссылка на 8/24/48/72 часа, по ней внешний человек открывает карточку **без входа в систему и только на чтение** — саму ссылку в кадр не выводить.

**Подробно — «Шахматка», обзор (1:30).**
1. Шапка таба: **«Поиск по номеру комнаты или ФИО клиента»** (ищет по гостю, должности, номеру комнаты, id заявки, авиакомпании), кнопка **«Легенда»** с полным списком цветов статусов, кнопка «Создать заявку».
2. Сетка: **всегда ровно один месяц**, стрелки ← → переключают месяц. **Зума и масштаба нет** — ширина суток считается автоматически по ширине окна.
3. Левая колонка номеров: «№ 151 Стандарт», мест «x 2», кроватей «x 2»; серая строка с «(не работает)» — выключенный номер.
4. Сказать главное про геометрию: **одна строка = один номер, каждое место — своя дорожка для перетаскивания.** На двухместном номере видно две дорожки.
5. Переключатель **«Квота» / «Резерв»**: меняет и правый список, и прозрачность блоков в сетке — неактивный тип гаснет. **Это не ошибка отрисовки.**
6. Навести на бронь, слегка двигая мышью — появится тултип с авиакомпанией, номером заявки, гостем, статусом и датами. Сказать: если навести и замереть, тултип исчезнет.

**Подробно — «Шахматка», работа мышью (2:00).**
1. **Разместить:** взять карточку из правого списка за иконку **«⋮⋮»**, перетащить в нужный номер и дату → модалка **«Подтверждение бронирования»** → «Подтвердить» → «Бронь успешно добавлена».
2. **Откатить:** повторить и в модалке нажать «Отмена» — заявка вернётся в правый список, на сервер ничего не уйдёт.
3. **Перенести в другой номер:** тянуть уже размещённый цветной блок в другую строку — **модалки нет**, изменение уходит сразу.
4. **Перенести внутри номера:** на другую дорожку того же номера → «Заявка перемещена в комнату N».
5. **Конфликты (показать специально):** занятые даты → «Место занято в комнате!», переполненный номер → отказ. Сказать: овербукинг здесь не «предупреждается», а физически невозможен — система ищет первое свободное место и отказывает, если мест нет.
6. **Изменить даты:** схватить блок за ручку **«⋮⋮»** у левого или правого края и потянуть по горизонтали, шаг — сутки; после отпускания откроется модалка правки дат и времени.
7. Клик по блоку коротко, не сдвигая мышь (разница между кликом и тягой около 10 px) → откроется карточка заявки.

**Подробно — «Номерной фонд» и «Тарифы» (1:30).**
1. **«Номерной фонд»**: номера сгруппированы по категориям; фильтры «Категория», «Квота / Резерв», «Поиск по номеру». **«Добавить номер»** → «Квота или резерв» + **«Тариф»**.
2. Сказать: цена и категория номера берутся из привязанного тарифа — поэтому тариф обязателен, а сами категории здесь не создаются. И: **строки шахматки — это ровно эти номера.**
3. **«Тарифы»** — четыре блока: **«Тарифы» / «Питание» / «Трансфер» / «Дополнительные услуги»**, в каждом две колонки цен: **«Цена по договору»** (наша закупка у гостиницы) и **«Цена для АК»** (что видит авиакомпания).
4. **«Добавить тариф»**: категория, название, стоимость, стоимость для АК, чекбокс **«Стоимость по запросу»** (в таблице вместо суммы будет «По запросу»), квадратура, описание, изображения — клик по картинке делает её обложкой.
5. Сказать: колонка «с НДС» считается интерфейсом по фиксированной ставке **5%**, это не поле. Строки «Питание» и «Трансфер» только редактируются, удалить их нельзя.
6. Открыть таб **«О гостинице»** и сказать: это ровно то, что видит авиакомпания и что открывается по публичной ссылке — галерея, описание, номера и цены «для АК».

4. Выключить «Доступ к разделу» в карточке «Трансфер» → «Взаимодействие» в этой же карточке погасло. Сказать: нельзя разрешить действия в разделе, который человек не видит.
5. Таб «Уведомления»: карточки «Заявки», «ФАП», «Сообщения», колонки **«на почту»** и **«в браузере»**.
6. «Сохранить» → показать изменившийся бейдж готовности отдела.
7. Сказать два факта: новый отдел создаётся со всеми доступами включёнными; «Гостиницы», «ГК Карс» и «Помощь» доступами не закрываются — их видят все.
8. Кнопка **«Должности и доступ»** → страница должностей: бейдж **«наследует»** (берёт доступ отдела) либо **«свой доступ»** (приоритетнее отдела).

# КАТЕГОРИЯ «ИНСТРУМЕНТЫ»

## 15. Отчёты v2 — 4:30

**Коротко.** Основной инструмент закрытия периода: Excel по заявкам эскадрильи за выбранный интервал, по авиакомпании или по гостинице. Отличие от старой версии — можно создать черновик, вручную проверить и поправить строки и только потом выгрузить.

**Подробно — создание (1:30).**
1. Переключатель **«Авиакомпании» / «Гостиницы»**, поиск по отчётам, кнопки **«Правила расчёта»** и **«Создать отчёт»**.
2. Сайдбар: «Тип отчёта» → «Авиакомпания» → **«Аэропорт»** (обязательный) → «Категория» / «Должность» / «Сотрудник» → блок **«Включить в отчёт»** (Проживание / Питание, хотя бы одно) → период.
3. Показать галку **«Проверить строки перед выгрузкой»** и назвать развилку: **без галки** — один шаг и сразу Excel (так выпускается большинство отчётов), **с галкой** — создаётся черновик.
4. Сказать про период: на сервер уходят не «даты», а `дата T00:10` и `дата T23:50`. Это часть расчёта, а не форматирование — сервер по этим границам обрезает заявку, и обрезанный край попадает в правила частичных суток.

**Подробно — черновик (2:00).**
1. Плашка **«Незавершённые черновики · N»** над таблицей → «Открыть». Бейдж **«устарел»** означает, что данные заявок могли измениться после создания черновика.
2. Заголовок «Черновик · Компания · период», чип **«Предупреждения · N»** — строки без суток или без цены.
3. Поправить «Сут.» и «Цена/сут.», показать иконку **«Вернуть расчёт сервера»** для одной строки и ссылку **«Сбросить все правки»**.
4. Удалить строку: корзина → «Удалить строку из отчёта?» → чип «Удалено · 1».
5. Главный тезис: пересчёт «сутки × цена» применяется **только к строкам, которые вы правили руками**. У нетронутых сумма приходит с сервера, где стоимость номера делится между соседями по временным сегментам — наивный пересчёт переписал бы чужие деньги.
6. **«Подтвердить и выгрузить»**: при несохранённых правках система сначала сохранит и только потом напечатает — печатается то, что лежит в базе, а не то, что на экране.
7. Сказать: очень большой черновик может не сохраниться из-за лимита запроса, в интерфейсе это выглядит как «ничего не произошло» — тогда разбить период.

**Подробно — правила расчёта суток (1:00).**
1. Кнопка **«Правила расчёта»** → сайдбар «Правила расчёта суток».
2. Группа **«Заезд»**: «раньше 06:00 → + 1 сут.», «раньше 14:00 → + 0.5 сут.». Группа **«Выезд»**: «позже 12:00 → + 0.5 сут.», «позже 18:00 → + 1 сут.».
3. Сказать: настройка одна общая на всю систему и применяется к **новым** отчётам; уже созданные черновики не пересчитываются — для актуальных цифр черновик надо пересоздать.
4. `Δ` править может только суперадмин; у роли «Диспетчер» режим просмотра с плашкой «Изменять правила может только супер-администратор».

## 21. Финал — 0:40

**Коротко.** Собрать картинку: **Заявки → Управление → Инструменты → Сервис**, и три потока заявок, которые не смешиваются — Эскадрилья это экипаж, ФАП это пассажиры, Трансфер это машины.

**Подробно.** Повторить три вещи, которые спрашивают чаще всего:
